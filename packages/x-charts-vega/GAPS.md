# Vega-Lite → MUI X Charts: support matrix and gaps

This document tracks what the wrapper translates natively, what renders with a visible approximation, and what cannot be expressed with `@mui/x-charts` components in any tier. The wrapper depends on `@mui/x-charts-premium` (which re-exports Pro and MIT): Premium-covered marks render with a watermark until a license key is set. Runtime code reports the same information per-spec through the `onGaps` prop as `TranslationGap` objects.

## Severity levels

- **✅ supported** — feature translates to native x-charts behavior.
- **⚠️ partial/approximated** — feature renders with a visible approximation or reduced functionality.
- **✅ supported (Premium)** — translates natively via `@mui/x-charts-pro`/`-premium` components (watermarked without a license key).
- **❌ unsupported (all tiers)** — no x-charts equivalent in any tier.

## Marks

All ten translatable mark kinds are implemented (`src/marks/*.ts`, dispatched from `markRegistry` in `src/marks/index.ts`), including the Premium-tier `rect` (heatmap), ranged `bar` (rangeBar), and `geoshape` (map) — the wrapper depends on `@mui/x-charts-premium`, which renders a watermark without a license key. Marks not in `markRegistry` (`boxplot`, `errorbar`, `errorband`, `text`, `image`) fall through to `compileSpec`'s "no compiler" branch, which reports an `unsupported` gap using the per-mark hint in `UNSUPPORTED_MARK_HINTS`.

| :----------------------- | :------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bar`                    | ✅ supported               | `marks/bar.ts` → `bar` series + `BarPlot`. Vertical (band x, quantitative y) and horizontal (auto-inferred, or explicit `mark.orient`, → `layout: 'horizontal'`). | `geoshape`               | ✅ supported (Premium)     | `marks/geoshape.ts` → the `@mui/x-charts-premium` Map (`GeoDataPlot` + `MapShapePlot` inside `ChartsGeoDataProviderPremium`; watermarked without a license). ## Encoding channels

Not all channels are utilized by all mark compilers; the table below lists what is _recognized_ by the wrapper and how it is handled. Mark-compiler implementation determines the final rendering.

| Channel                    | Status                                                    | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| :------------------------- | :-------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x`                        | ✅ supported                                              | Positional. Band/point scale for categorical/temporal values (temporal channels are approximated as a discrete scale — see Scales & axes); linear/log/pow/sqrt/symlog for quantitative.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `y`                        | ✅ supported                                              | Positional. Same scale handling as `x`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `x2`                       | ⚠️ partial (Premium for bars)                             | On horizontal bar marks, `x` + `x2` field pairs translate to a Premium `rangeBar` series (`marks/bar.ts`; watermarked without a license). Rule marks report their own segment gaps. All other marks drop the second endpoint with a `channel:x2` `unsupported` gap (`compile/scales.ts`).                                                                                                                                                                                                                                                                                                                                                              |
| `y2`                       | ⚠️ partial (Premium for bars)                             | Same as `x2`, transposed: vertical bar marks with `y` + `y2` field pairs become `rangeBar` series; other marks drop the endpoint with `channel:y2`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `xOffset` / `yOffset`      | ⚠️ partial                                                | Only `marks/bar.ts` reads these (`xOffset` for vertical bars, `yOffset` for horizontal bars) to switch a color-split bar series from stacked to grouped; a gap (`encoding:bar-offset-mismatch`, `partial`) is reported if the offset field differs from the color field. Every other mark compiler never reads `xOffset`/`yOffset` at all — the channel is silently ignored with no gap on non-bar marks.                                                                                                                                                                                                                                          |
| `color`                    | ⚠️ partial                                                | `compile/color.ts` (`resolveColor`). Nominal/ordinal field → one series per distinct value (in `scale.domain` order when given, else first-appearance order), with `scale.range` or a mapped `scale.scheme` name (see the categorical scheme table in `color.ts`) supplying colors; unmapped scheme names fall back to the chart's default palette with a `partial` gap. Quantitative/temporal field → a continuous (or, when `bin` is set, piecewise) axis `colorMap` computed from the data extent, always with a `partial` gap since only some x-charts series types honor axis `colorMap`. Static color via a `value` def is applied directly. |
| `fill` / `stroke`          | ⚠️ partial                                                | `resolveColor` treats `color` ?? `fill` ?? `stroke` as the color source (Vega shorthand precedence); if both `fill` and `stroke` are given, `stroke` is dropped with an `ignored` gap (`encoding:color-fill-stroke-conflict`).                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `opacity`                  | ⚠️ ignored / unsupported                                  | Never affects rendering. A field-driven `opacity`/`fillOpacity` is reported `unsupported` (`encoding:opacity-field-unsupported` in `color.ts`, `encoding:opacity` in `marks/point.ts`); mark-level static `opacity`/`fillOpacity`/`strokeOpacity` on line/area marks is reported `ignored` (`mark:opacity` in `marks/lineArea.ts`). No mark compiler applies opacity to a series.                                                                                                                                                                                                                                                                  |
| `size`                     | ⚠️ partial                                                | Only `marks/point.ts` reads `size`. A static `mark.size` (area-like, per Vega-Lite convention) is approximated into a radius-like `markerSize` via `Math.sqrt(size)` (`partial` gap, `mark:point-size-approximation`); a field-driven `encoding.size` is unsupported (`partial` gap, `encoding:size-field`) — MIT scatter has no per-point size. Not read by any other mark compiler.                                                                                                                                                                                                                                                              |
| `shape`                    | ❌ unsupported (all tiers)                                | `marks/point.ts` reports an `ignored` gap (`encoding:shape`); x-charts scatter markers are visually uniform.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `angle`                    | ❌ unsupported (all tiers)                                | Declared in the type but never read anywhere in the compiler; no mark or gap references it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `theta` / `theta2`         | `theta` ✅ supported, `theta2` ❌ unsupported (all tiers) | `marks/arc.ts`: `theta` (field, `datum`, or static `value`) → slice `value`, with a `partial` fallback to a quantitative `y` when absent. `theta2` is read only to fire an `unsupported` gap (`encoding:arc-theta2`); a single pie series cannot express a per-slice start/end radius or angle range.                                                                                                                                                                                                                                                                                                                                              |
| `radius` / `radius2`       | ❌ unsupported (all tiers)                                | These are the _encoding channels_ (as opposed to `mark.innerRadius`/`mark.outerRadius`, which ARE supported — see the Marks table). `marks/arc.ts` reads `radius`/`radius2` only to fire `unsupported` gaps (`encoding:arc-radius`, `encoding:arc-radius2`); a single pie series has one inner/outer radius, not a per-slice value.                                                                                                                                                                                                                                                                                                                |
| `detail`                   | ❌ unsupported (all tiers)                                | Declared in the type but never read anywhere in the compiler; grouping-without-encoding has no x-charts equivalent and produces no gap (silently ignored).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `order`                    | ⚠️ ignored                                                | Only `marks/arc.ts` reads `order`, to fire an `ignored` gap (`encoding:arc-order`) — pie slices keep row order instead. Not read by any other mark compiler (bar/line/point series order follows color-group iteration order, not an `order` channel).                                                                                                                                                                                                                                                                                                                                                                                             |
| `text`                     | ❌ unsupported (all tiers)                                | Only `marks/arc.ts` reads `text`, to fire an `unsupported` gap (`encoding:arc-text-label`) pointing at the `arcLabel` prop as an unwired alternative. Free-form text marks have no primitive in any mark compiler.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `tooltip`                  | ⚠️ ignored                                                | Declared in the type but never read by the compiler. `<ChartsTooltip />` is always mounted by `VegaLiteChart.tsx` and shows x-charts' own default series/point tooltip regardless of this channel; the spec's `tooltip` field list is not consulted to customize its content.                                                                                                                                                                                                                                                                                                                                                                      |
| `href`                     | ❌ unsupported (all tiers)                                | Declared in the type but never read anywhere; no gap is fired for it either. Workaround: use external click handlers on the chart container.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `key`                      | ⚠️ ignored                                                | Declared in the type but never read; data is matched by array index (via `categoryIndex`/`categoryKey` on the resolved axis field), not by `key`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `facet` / `row` / `column` | ❌ unsupported (all tiers)                                | `normalize/index.ts` reports an `unsupported` gap (`encoding:facet`) when any of `encoding.row`/`encoding.column`/`encoding.facet` is present; the spec is normalized as if the facet channel were absent (no split rendering).                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Data & transforms

### Data source

| Feature                                           | Status                     | Notes                                                                                                                                                                                                     |
| :------------------------------------------------ | :------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inline values (`data.values` as object array)     | ✅ supported               | `normalize/index.ts` `resolveRows`.                                                                                                                                                                       |
| Named datasets (`data.name` + `datasets` map)     | ✅ supported               | Resolved via the `datasets` prop (host-provided) merged over `spec.datasets`, host takes precedence; a missing name reports an `unsupported` gap (`data:named-missing`) and falls back to inherited rows. |
| URL loading (`data.url`)                          | ❌ unsupported (all tiers) | `unsupported` gap (`data:url`); no HTTP fetching in the wrapper. Workaround: fetch data yourself and pass via the `data` prop or `datasets`.                                                              |
| String payloads (`data.values` as CSV/TSV string) | ❌ unsupported (all tiers) | `unsupported` gap (`data:string-values`); string parsing not implemented. Workaround: parse to a JSON array first.                                                                                        |
| `data.format` (CSV parsing, delimiter, etc.)      | ⚠️ ignored                 | Declared in the `VegaData` type but never read in `normalize/index.ts`; no gap is fired for it. Data must already be parsed into row objects.                                                             |

### Transforms

Transforms are applied sequentially in order (`transforms/index.ts` `applyTransforms`, plus the inline encoding-level pass `applyEncodingTransforms` in `transforms/encoding.ts` for `aggregate`/`bin`/`timeUnit` declared directly on a channel field def). Unrecognized top-level transform kinds are skipped with a gap.

| Transform       | Status                     | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :-------------- | :------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aggregate`     | ✅ supported               | `transforms/aggregate.ts` (top-level) and the inline pass in `transforms/encoding.ts`, sharing the op evaluator in `transforms/aggregateOps.ts`. Full group-by aggregation: `count`, `valid`, `missing`, `distinct`, `sum`, `product`, `mean`/`average`, `min`, `max`, `median`, `q1`, `q3`, `variance`, `variancep`, `stdev`, `stdevp`, `stderr`. `argmin`/`argmax` are recognized but not implemented (`unsupported` gap, `aggregate:argminmax`).                                                                                                                                                                                                                                                                                                                                                                                                              |
| `fold`          | ✅ supported               | Inline in `transforms/index.ts` `applyTransforms` (not a separate module). Pivots columns to rows (key–value pairs); `fold.as` defaults to `['key', 'value']`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `filter`        | ✅ supported               | `transforms/filter.ts`. Field predicates (`{field, equal/lt/lte/gt/gte/range/oneOf/valid}`, optionally with a `timeUnit` qualifier — compared against the raw value with a `partial` gap since it isn't actually truncated first), logical composition (`and`/`or`/`not`, three-valued to fail open on unsupported sub-predicates), and Vega expression strings (via the shared safe evaluator in `transforms/calculate.ts` — **never** `eval()`/`new Function()`). Selection/param predicates and malformed shapes report an `unsupported` gap and keep every row (fail open).                                                                                                                                                                                                                                                                                  |
| `calculate`     | ✅ supported               | `transforms/calculate.ts`. A hand-rolled recursive-descent parser/evaluator (never `eval()`) for a safe expression subset: arithmetic, string concatenation, comparisons, ternaries, `&&`/\|\|/`!`, `datum.field`/`datum['field']` access, and an allow-listed function set (`abs`, `round`, `floor`, `ceil`, `sqrt`, `min`, `max`, `length`, `upper`, `lower`, `toNumber`, `toString`, `year`, `month`, `date`). Syntax/semantics outside this subset report an `unsupported` gap (`transform:calculate`) and leave the target field `null`.                                                                                                                                                                                                                                                                                                                    |
| `bin`           | ✅ supported               | `transforms/bin.ts` (top-level `applyBinTransform`, and inline `applyInlineBin` wired from `transforms/encoding.ts`). d3-style "nice" binning honoring `maxbins` (default 10), an explicit `step`, and an explicit `extent` (values outside an _explicit_ extent are excluded; a _derived_ extent always covers every value). The top-level transform writes `as` (bin start) and `as`+`_end` (or `as[1]`); the inline (encoding-channel) form writes a synthetic `"start–end"` ordinal label column so histograms go through the existing band-scale axis path. `bin: "binned"` (pre-binned data) is recognized but not implemented (`partial` gap, `encoding:bin-binned`) and falls back to the raw unbinned field.                                                                                                                                            |
| `timeUnit`      | ✅ supported               | `transforms/timeUnit.ts` (top-level `applyTimeUnitTransform`, and inline `applyInlineTimeUnit`). Calendar truncation for `year`, `quarter`, `month`, `week`, `date`, `hours`, `minutes`, `seconds`, `milliseconds`, and the composites `yearquarter`/`yearmonth`/`yearmonthdate`/`yearweek`/`monthdate`/`hoursminutes`/`hoursminutesseconds` (each truncates to its finest named component while keeping the real calendar date — a documented simplification vs. Vega-Lite's cross-year cyclic alignment for a single unit like `month`). The cyclic `day` (day-of-week) unit is supported but always reports a `partial` gap (`timeUnit:day`) since it maps onto a synthetic reference week, not the real date. Units outside this set (e.g. `dayofyear`) report an `unsupported` gap (`timeUnit:<unit>`) and pass rows through with a `null`/unwritten field. |
| `window`        | ❌ unsupported (all tiers) | No x-charts primitive for window functions (rank, row_number, lag, lead, etc.). Workaround: apply window logic in preprocessing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `joinaggregate` | ❌ unsupported (all tiers) | Window aggregation (e.g., mean across all groups) has no x-charts equivalent. Workaround: aggregate in preprocessing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `stack`         | ❌ unsupported (all tiers) | Explicit stacking transform not needed; x-charts bar/line infer `stack` from encoding. Use the encoding `stack` property instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `lookup`        | ✅ supported (inline)      | `transforms/lookup.ts` — first-match join on `from.key` with `fields`/`as` renaming, whole-datum-under-`as`, `default` for non-matches, and dotted-path keys on GeoJSON features (choropleth joins). `from.data` must be inline `values`; `url`/named datasets are gaps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

| `regression`    | ❌ unsupported (all tiers) | Regression-line fitting has no x-charts equivalent. | `loess`         | ❌ unsupported (all tiers) | LOESS smoothing has no x-charts equivalent. Workaround: smooth data in preprocessing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `impute`        | ❌ unsupported (all tiers) | Missing-value imputation has no x-charts equivalent. Workaround: impute before passing data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `flatten`       | ❌ unsupported (all tiers) | Nested array flattening has no x-charts equivalent. ## Scales & axes

### Scale types

`compile/scales.ts` `resolveChannelAxis` resolves positional (x/y) scales. Temporal data is approximated as a discrete band/point scale over the sorted date domain (a `partial` gap, `scale:temporal-point-approximation`, is always reported for a temporal channel).

| Scale type                                           | Status       | Notes                                                                                                                                                                                                                                                                                      |
| :--------------------------------------------------- | :----------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `linear`                                             | ✅ supported | Default for quantitative axes.                                                                                                                                                                                                                                                             |
| `log`                                                | ✅ supported | Logarithmic scale.                                                                                                                                                                                                                                                                         |
| `pow`                                                | ⚠️ partial   | Scale type maps through, but `scale.exponent` is declared in the `VegaScale` type and never read by `resolveChannelAxis` — the x-charts default exponent is always used, not the spec's value.                                                                                             |
| `sqrt`                                               | ✅ supported | Square-root scale.                                                                                                                                                                                                                                                                         |
| `symlog`                                             | ⚠️ partial   | Scale type maps through, but `scale.constant` (the symlog linear-region constant) is never read — the x-charts default is always used.                                                                                                                                                     |
| `time` / `utc`                                       | ⚠️ partial   | Not a continuous time scale: approximated as a discrete band/point scale over the sorted `Date` domain (see above).                                                                                                                                                                        |
| `band`                                               | ✅ supported | Categorical; used by default for bar/rect marks (`channelHasBarMark`).                                                                                                                                                                                                                     |
| `point`                                              | ✅ supported | Categorical; used by default for non-bar marks.                                                                                                                                                                                                                                            |
| `ordinal`                                            | ✅ supported | An explicit `scale.type: 'ordinal'` maps to x-charts' `band` scale (`explicitDiscreteScaleType`), matching Vega's own convention that an ordinal position scale is a band scale. (Not "treated as point" — that was true of a prior implementation but is not what the current code does.) |
| Unsupported types (e.g., `sequential`, custom names) | ⚠️ partial   | An unrecognized `scale.type` string falls back to `linear` with a `partial` gap (`scale:<type>`) — the chart still renders (with the wrong scale semantics), it does not drop the axis.                                                                                                    |

Band-scale `padding`/`paddingInner`/`paddingOuter` (Vega-Lite spacing knobs) are declared in the `VegaScale` type but never read anywhere in `compile/scales.ts` — see the Scale properties table below.

### Scale properties

| Property                                    | Status       | Notes                                                                                                                                                                                                                                                                                                                   |
| :------------------------------------------ | :----------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `domain`                                    | ✅ supported | Quantitative: `[min, max]` (numeric entries only) → axis `min`/`max`. Categorical: auto-collected from data across every layer sharing the channel, in first-appearance order (or `sort` order — see Axis configuration).                                                                                               |
| `range`                                     | ⚠️ ignored   | On a _positional_ (x/y) channel: never read in `compile/scales.ts`. (On the `color` channel, `scale.range` IS read — see the Encoding channels `color` row.)                                                                                                                                                            |
| `scheme`                                    | ⚠️ ignored   | Same distinction as `range`: irrelevant/unread on positional channels; read on `color` (Encoding channels table).                                                                                                                                                                                                       |
| `zero`                                      | ⚠️ ignored   | Declared in the type; a code comment in `compile/scales.ts` notes the x-charts default already lets a bar-anchored axis float from zero, but there is no branch that actually reads `scale.zero`.                                                                                                                       |
| `nice`                                      | ⚠️ partial   | Only the `false` value has an effect: `scale.nice === false` sets the quantitative axis's `domainLimit` to `'strict'` (an exact, non-rounded domain). `true` (the Vega-Lite default) or an explicit tick-count number are not distinguished from "unset" — the x-charts default (non-strict) domain is used either way. |
| `reverse`                                   | ✅ supported | `scale.reverse === true` sets `reverse: true` on the axis config, for both categorical and quantitative channels.                                                                                                                                                                                                       |
| `padding` / `paddingInner` / `paddingOuter` | ⚠️ ignored   | Declared in the `VegaScale` type but never read anywhere in `compile/scales.ts`; band-scale spacing always uses the x-charts axis default, regardless of what the spec requests.                                                                                                                                        |

### Axis configuration

All of the below is read from a field def's `axis` object (`buildAxisExtras` / `axisTitle` in `compile/scales.ts`); a bare `axis: null` on the field def removes the axis entirely (maps to x-charts' `position: 'none'`, which reserves layout space but hides the axis — a real, working x-charts feature).

| Axis feature                    | Status                | Notes                                                                                                                                                                                                                                                                    |
| :------------------------------ | :-------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`                         | ✅ supported          | Explicit `axis.title` (including `null` to suppress it) wins, then the field def's own `title`, then an auto-derived name. Encoding-level aggregates derive a human-readable title during the rewrite (`transforms/encoding.ts`), e.g. "MEAN of v" / "Count of Records". |
| `labels`                        | ⚠️ partial            | Only `labels: false` has an effect (`tickLabelStyle.display = 'none'`); there is no handling for `labels: true` beyond the (already-default) visible state.                                                                                                              |
| `ticks`                         | ⚠️ ignored            | Declared in the `VegaAxis` type but never read by `buildAxisExtras`; tick marks always render via the x-charts default regardless of `axis.ticks: false`.                                                                                                                |
| `grid`                          | ✅ supported          | `resolveAxes` sets `grid.vertical`/`grid.horizontal` from `encoding.x.axis.grid`/`encoding.y.axis.grid`; `<ChartsGrid>` renders accordingly.                                                                                                                             |
| `orient`                        | ⚠️ partial            | `mapOrient` accepts `'top'`/`'bottom'` for `x` and `'left'`/`'right'` for `y` (the other pair is silently dropped, not just "may be overridden").                                                                                                                        |
| `format`                        | ⚠️ ignored (reported) | A string `axis.format` (d3-format / d3-time-format) always reports a `partial` gap (`scale:axis-format`) and is never applied; x-charts' own default number/date formatting is used unconditionally.                                                                     |
| `tickCount`                     | ⚠️ partial            | Passed straight through as `tickNumber`; x-charts treats it as a hint, not an exact count.                                                                                                                                                                               |
| `values`                        | ⚠️ partial            | Passed straight through as `tickInterval`; x-charts may still adjust what's actually rendered.                                                                                                                                                                           |
| `labelAngle`                    | ⚠️ partial            | Passed straight through as `tickLabelStyle.angle`; no gap reported (present since the mapping is direct), but x-charts may override for collision avoidance.                                                                                                             |
| `domain` (axis-line visibility) | ⚠️ ignored            | Declared in the `VegaAxis` type but never read by `buildAxisExtras`; the axis line always renders via the x-charts default. (Not to be confused with `scale.domain`, the data-domain array, which IS supported — see Scale properties.)                                  |
| Full axis removal               | ✅ supported          | `axis: null` on the field def → `position: 'none'` (see the note above the table). There is no separate `axis.disable` property in Vega-Lite or in this wrapper's `VegaAxis` type; `axis: null` is the correct/only way to hide an axis.                                 |

## How gaps are reported at runtime

When the wrapper encounters untranslatable Vega-Lite features, it collects them as `TranslationGap` objects and returns them via the `onGaps` prop. Each gap has a `code` (e.g., `mark:geoshape`, `encoding:facet`), a human-readable `message` (often including workarounds and tier pointers), a `severity` (unsupported/partial/ignored), and optionally a `path` into the input spec (e.g., `layer[0].encoding.color`).

Example usage:

```tsx
import { VegaLiteChart } from '@mui/x-charts-vega';

const spec = {
  mark: 'geoshape',
  // ...
};

const [gaps, setGaps] = useState([]);

<VegaLiteChart spec={spec} onGaps={setGaps} />;

// gaps[0].code === 'mark:boxplot'
// gaps[0].message === "boxplot has no x-charts equivalent in any tier."
// gaps[0].severity === 'unsupported'
```

Render gaps as warnings in your UI, or use them to fall back to a different visualization. The wrapper always attempts a best-effort render even when gaps are present.
