# Vega-Lite → MUI X Charts: support matrix and gaps

This document tracks what the wrapper translates natively, what renders with a visible approximation, and what cannot be expressed with `@mui/x-charts` components in any tier. The wrapper depends on `@mui/x-charts-premium` (which re-exports Pro and MIT): Premium-covered marks render with a watermark until a license key is set. Runtime code reports the same information per-spec through the `onGaps` prop as `TranslationGap` objects.

## Severity levels

- **✅ supported** — feature translates to native x-charts behavior.
- **⚠️ partial/approximated** — feature renders with a visible approximation or reduced functionality.
- **✅ supported (Premium)** — translates natively via `@mui/x-charts-pro`/`-premium` components (watermarked without a license key).
- **❌ unsupported (all tiers)** — no x-charts equivalent in any tier.

## Marks

All fifteen translatable mark kinds are implemented (`src/marks/*.ts`, dispatched from `markRegistry` in `src/marks/index.ts`): the Premium-tier `rect` (heatmap), ranged `bar` (rangeBar), and `geoshape` (map) render through `@mui/x-charts-premium` (watermarked without a license key), and `boxplot`/`errorbar`/`errorband`/`text`/`image` render through the custom overlay pipeline (`src/overlays` — plain SVG surface children built on the public `useXScale`/`useYScale` hooks, the same composition pattern as `ChartsReferenceLine`). Unknown mark strings fall through to a generic `unsupported` gap.

| Vega-Lite mark           | Status                  | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| :----------------------- | :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bar`                    | ✅ supported            | `marks/bar.ts` → `bar` series + `BarPlot`. Vertical (band x, quantitative y) and horizontal (auto-inferred, or explicit `mark.orient`, → `layout: 'horizontal'`). Color-field splitting into one series per group, stacked by default (`stack: 'zero'`/`'normalize'`→`stackOffset: 'expand'`/`'center'`→`'silhouette'`), or grouped (unstacked) when `xOffset`/`yOffset` is present. Pairing the value channel with its `2` twin (`y`+`y2` / `x`+`x2` field pairs) emits a Premium `rangeBar` series instead (watermarked without a license). `mark.cornerRadius` (a single positive number) maps to the chart-wide `BarPlot` `borderRadius` (`partial` — applied to every bar series, not per-mark; a per-mark conflict reports `mark:bar-corner-radius-conflict`); per-corner radii (`cornerRadiusTopLeft` etc.), a non-positive/expression `cornerRadius`, and `mark.size`/`mark.binSpacing` are recognized but `ignored` (see the Config section below).                                                                                                                                                                                                                                               |
| `line`                   | ⚠️ partial/approximated | `marks/lineArea.ts` → `line` series + `LinePlot`. Index-aligned to `x`'s discrete category domain; missing cells are `null` and `connectNulls` is always `false`. Color-field splitting; `mark.interpolate` mapped where an exact `CurveType` exists ('linear', 'monotone'→'monotoneX', 'natural', 'step'/'step-before'/'step-after'), else approximated to `'catmullRom'` with a `partial` gap ('basis'/'bundle'/'cardinal'/'catmull-rom') or falls back to `'linear'` with a gap for anything else. `mark.point` → `showMark` + `MarkPlot` overlay. Temporal `x` values are coerced to `Date` before category alignment (regression-tested in the golden suite). Over a **continuous quantitative x** axis (no index-aligned category domain — e.g. a `regression`/`loess` trend line or a function plot) the line renders as a polyline through the `segments` overlay instead of an x-charts series, one x-sorted path per color group.                                                                                                                                                                                                                                                                |
| `area`                   | ⚠️ partial/approximated | Same compiler as `line` (`marks/lineArea.ts`) with `area: true` + `AreaPlot`; stacks by default when color-split (Vega-Lite's `stack: 'zero'` default for areas). Subject to the same interpolate-approximation notes as `line`. Like `line`/`trail`, an `area` over a **continuous quantitative x** axis now renders through the overlay pipeline instead of being dropped — one filled `band` overlay per color group (upper edge = the y value, lower edge = the zero baseline, x-sorted); the layer is only dropped (`mark:line-continuous-x`) when fewer than two numeric points survive. A gradient `mark.color`/`fill` (`{gradient, stops}`) is approximated by its highest-offset stop color (x-charts fills are solid), with an `ignored` `mark:gradient-fill` gap.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `point` / `circle`       | ⚠️ partial/approximated | `marks/point.ts` → `scatter` series. Both positional channels quantitative/temporal → scatter data; one categorical channel → strip plot against the band/point axis (temporal/nominal/ordinal values are coerced via `resolveAxisValue`, unlike `line`/`area`). Color-field splitting. `mark.size` (static) is approximated via `Math.sqrt(size)` into `markerSize` (`partial` gap); a field-driven `encoding.size` maps to per-point `sizeValue` + a zAxis `sizeMap` (real bubble charts). `shape`/`filled: false` are ignored; a static `mark.opacity`/`fillOpacity` (or a value-def `opacity` encoding) is now baked into the marker color (see the Config mark-style row), while `strokeOpacity` stays `ignored`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `square`                 | ⚠️ partial/approximated | Same compiler as `point`; renders as the standard circular scatter marker — the square shape is dropped (`ignored` gap).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `tick`                   | ✅ supported            | `marks/point.ts` → a `{kind: 'segments'}` overlay: short perpendicular line segments at each position (rendered by `overlays/Segments.tsx`), no longer circular-point approximations. A single positional channel (only `x` or only `y`) renders a 1D strip/rug plot — the perpendicular side becomes a synthetic one-category band (`scales.ts`) the ticks span across.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `trail`                  | ⚠️ partial/approximated | Compiled by `marks/lineArea.ts` as a plain `line` series (`partial` gap: `trail`'s per-point stroke-width-by-field has no x-charts equivalent, so the line renders with uniform width). Subject to the same temporal-axis bug as `line`/`area`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `arc`                    | ✅ supported            | `marks/arc.ts` → `pie` series + `PiePlot`. `theta` (quantitative, aggregated or not) → slice `value`; falls back to a quantitative `y` with a `partial` gap when `theta` is absent. `color` field → slice `label` (one datum per distinct value) and slice color (from an explicit `scale.range`, positionally matched to `scale.domain` or first-appearance order). `mark.innerRadius`/`outerRadius`/`cornerRadius` map directly; `mark.padAngle` (radians) is converted to `paddingAngle` (degrees). No cartesian axes are rendered for a polar chart. **Not** covered: the `radius`/`radius2`/`theta2` _encoding channels_ (as opposed to the `mark.innerRadius`/`outerRadius` _mark_ properties, which are wired) — see the Encoding channels table. `encoding.text` maps to the pie series' `arcLabel` (see the `text` mark row); slice ordering (`encoding.order`) now sorts the slices — a `field` with an optional ascending/descending `sort` (tie-broken by row order; when the order field was consumed by aggregation, the slice's aggregated `value` is used). An uninterpretable `order` (multi-field, sort-by-encoding) records a `partial` gap (`encoding:arc-order`) and keeps row order. |
| `rule`                   | ⚠️ partial/approximated | `marks/rule.ts` → one or more `ChartsReferenceLine`s (not a mark/series). Only `y` (datum, aggregated, or per-distinct-value field) → horizontal line(s); only `x` → vertical line(s), capped at 10 lines with a `partial` gap beyond that. Mark `color`/`strokeWidth`/`strokeDash` → `lineStyle`. A rule with _both_ `x` and `y` (no `x2`/`y2`) is approximated as two full crossing reference lines instead of a single point marker (`partial` gap). Spanning rules now render as a `{kind: 'segments'}` overlay (no longer dropped): `x`→`x2` draws a horizontal segment per row (anchored on the perpendicular axis from `y`/`yOffset`, or a shared categorical y axis), `y`→`y2` the transposed vertical case, and all four of `x`/`y`/`x2`/`y2` an arbitrary diagonal segment per row. Only a span with no resolvable perpendicular anchor (no `y`/`yOffset` and no categorical axis to distribute across) is genuinely unanchorable and dropped with a `partial` gap (`mark:rule-segment-x-no-anchor`/`mark:rule-segment-y-no-anchor`).                                                                                                                                                            |
| `rect`                   | ✅ supported (Premium)  | `marks/rect.ts` → `heatmap` series + `HeatmapPlot` (from `@mui/x-charts-pro`; watermarked without a license). Needs two discrete positional channels and a quantitative color/fill channel (the cell value); the color scale becomes a `zAxis` `colorMap` (continuous, or piecewise when binned). Ranged rects (`x2`/`y2` spans) remain `unsupported`; per-cell stroke/opacity styling is `ignored`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `geoshape`               | ✅ supported (Premium)  | `marks/geoshape.ts` → the `@mui/x-charts-premium` Map (`GeoDataPlot` + `MapShapePlot` inside `ChartsGeoDataProviderPremium`; watermarked without a license). GeoJSON features come from the unit's rows (Feature rows or a single FeatureCollection). Outline maps render `GeoDataPlot` only; a color/fill field over feature properties produces a `mapShape` choropleth series with per-entry colors. TopoJSON topologies convert via `data.format.type: 'topojson'` + `format.feature`; an inline `lookup` transform joins tabular values onto each **feature** (not the wrapping collection) — and because x-charts matches shapes to series data only by `feature.properties.name`, a feature's numeric `id` is bridged into `properties.name` so an id-keyed choropleth (e.g. US counties + a `rate` dataset joined on FIPS `id`) colors correctly; quantitative/temporal color fields produce a real color (z) axis with a `ContinuousColorLegend`/`PiecewiseColorLegend`; projection `rotate`/`scale`/`translate` forward to the provider. Not covered: sphere/graticule generators, `center`/`parallels`/`clipAngle`/`fit` projection params, `lookup` from `url`/named datasets.                 |
| `boxplot`                | ✅ supported (overlay)  | `marks/boxplot.ts` → `{kind: 'boxes'}` overlay (`overlays/BoxPlot.tsx`): quartiles via the shared aggregate ops, whiskers per `mark.extent` (default 1.5×IQR clamped to in-fence data; `'min-max'`; numeric k), outlier dots, both orientations. Color-field splits render dodged (grouped) boxes — one box per group within each category, positioned side-by-side, with a custom swatch legend (via `CompiledChart.overlayLegend`, rendered by the shell) identifying each group. Sub-mark styling (`median`/`box`/`rule`/`ticks`/`outliers` color+opacity, or `false` to hide) is honored via `resolveSubMark`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `errorbar` / `errorband` | ✅ supported (overlay)  | `marks/errorBar.ts` → `{kind: 'errorBars'}` / `{kind: 'band'}` overlays (`overlays/ErrorBars.tsx`): per-category intervals per `mark.extent` ('stderr' default, 'stdev', 'iqr', 'ci' approximated as mean ± 1.96×stderr — `partial`). Errorbar supports both orientations; a transposed (categorical-y) band renders via an orientation-aware band path. A color-field split is now honored: error bars dodge side-by-side (one interval per group per category, offset within the band); error bands render one semi-transparent overlaid `band` per group. Both emit a custom swatch legend via `CompiledChart.overlayLegend` (rendered by the shell), mirroring the box-plot split. Typically layered with line/point marks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `text`                   | ✅ supported (overlay)  | `marks/textMark.ts` → `{kind: 'text'}` overlay (`overlays/TextMarks.tsx`): per-row SVG labels with dx/dy offsets and fontSize/font/weight/color/align/baseline styling (align/baseline default to centered — `textAnchor: middle`, `dominantBaseline: middle` — matching Vega-Lite, so value labels sit centered on the point they annotate). A translatable `format` string (d3-format / d3-time-format) is applied; an untranslatable one reports a `partial` gap. `{test, value}` predicate conditions (and first-match arrays) apply per-row value overrides; param-ref/field/unparseable conditions report a gap and fall back to the base value. On arc marks, `encoding.text` maps to the pie series' `arcLabel` instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `image`                  | ✅ supported (overlay)  | `marks/imageMark.ts` → `{kind: 'image'}` overlay: `<image href>` per row from the `url` channel, `mark.width`/`height` (default 20px). `aspect: false` maps to `preserveAspectRatio="none"` (images stretch); the default preserves the aspect ratio, matching Vega-Lite.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

## Encoding channels

Not all channels are utilized by all mark compilers; the table below lists what is _recognized_ by the wrapper and how it is handled. Mark-compiler implementation determines the final rendering.

| Channel                    | Status                                                    | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :------------------------- | :-------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x`                        | ✅ supported                                              | Positional. Band/point scale for categorical values; a continuous `time`/`utc` scale for temporal values on continuous-friendly marks, else a discrete temporal scale (see Scales & axes); linear/log/pow/sqrt/symlog for quantitative.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `y`                        | ✅ supported                                              | Positional. Same scale handling as `x`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `x2`                       | ⚠️ partial (Premium for bars)                             | On horizontal bar marks, `x` + `x2` field pairs translate to a Premium `rangeBar` series (`marks/bar.ts`; watermarked without a license). Rule marks report their own segment gaps. All other marks drop the second endpoint with a `channel:x2` `unsupported` gap (`compile/scales.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `y2`                       | ⚠️ partial (Premium for bars)                             | Same as `x2`, transposed: vertical bar marks with `y` + `y2` field pairs become `rangeBar` series; other marks drop the endpoint with `channel:y2`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `xOffset` / `yOffset`      | ⚠️ partial                                                | Only `marks/bar.ts` reads these (`xOffset` for vertical bars, `yOffset` for horizontal bars) to switch a color-split bar series from stacked to grouped; a gap (`encoding:bar-offset-mismatch`, `partial`) is reported if the offset field differs from the color field. Every other mark compiler never reads `xOffset`/`yOffset` at all — the channel is silently ignored with no gap on non-bar marks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `color`                    | ⚠️ partial                                                | `compile/color.ts` (`resolveColor`). Nominal/ordinal field → one series per distinct value (in `scale.domain` order when given, else first-appearance order), with `scale.range` or a mapped `scale.scheme` name supplying colors — the scheme table in `color.ts` now covers true categorical schemes (`category*`/`tableau*`/`set*`/`accent`/`dark2`/`paired`/`pastel1`/`pastel2`), single-hue sequential ramps used on discrete fields (`blues`/`greens`/`oranges`/`purples`/`reds`), and perceptual/multi-hue schemes (`viridis`/`plasma`/`inferno`/`magma`/`cividis`/`turbo`/`rainbow`/`sinebow`/`spectral`, approximated to the closest multi-hue palette); unmapped scheme names fall back to the chart's default palette with a `partial` gap. Quantitative/temporal field → a continuous (or, when `bin` is set, piecewise) axis `colorMap` computed from the data extent, always with a `partial` gap since only some x-charts series types honor axis `colorMap`. Static color via a `value` def is applied directly. |
| `fill` / `stroke`          | ⚠️ partial                                                | `resolveColor` treats `color` ?? `fill` ?? `stroke` as the color source (Vega shorthand precedence); if both `fill` and `stroke` are given, `stroke` is dropped with an `ignored` gap (`encoding:color-fill-stroke-conflict`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `opacity`                  | ⚠️ partial                                                | A constant `mark.opacity`/`fillOpacity` (or a value-def `opacity` encoding, `>= 0` and `< 1`) is baked into the resolved series/marker color as an rgba alpha centrally in `compile/index.ts` (`staticMarkOpacity` + `applyAlpha`), affecting bar/line/area/arc/scatter. A field-driven `opacity`/`fillOpacity` remains `unsupported` (`encoding:opacity-field-unsupported` in `color.ts`) — x-charts has no per-point opacity — and a separate `strokeOpacity` on line/scatter marks stays `ignored` (`encoding:opacity`), since the single series color has no distinct stroke alpha.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `size`                     | ✅ supported (points)                                     | `marks/point.ts`: a field-driven `encoding.size` maps to per-point `sizeValue` plus a zAxis `sizeMap` (real bubble charts via x-charts' size scale); a static `mark.size` is approximated into `markerSize` via `Math.sqrt(size)` (`partial`). Not read by other mark compilers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `shape`                    | ❌ unsupported (all tiers)                                | `marks/point.ts` reports an `ignored` gap (`encoding:shape`); x-charts scatter markers are visually uniform.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `angle`                    | ❌ unsupported (all tiers)                                | Declared in the type but never read anywhere in the compiler; no mark or gap references it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `theta` / `theta2`         | `theta` ✅ supported, `theta2` ❌ unsupported (all tiers) | `marks/arc.ts`: `theta` (field, `datum`, or static `value`) → slice `value`, with a `partial` fallback to a quantitative `y` when absent. `theta2` is read only to fire an `unsupported` gap (`encoding:arc-theta2`); a single pie series cannot express a per-slice start/end radius or angle range.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `radius` / `radius2`       | ❌ unsupported (all tiers)                                | These are the _encoding channels_ (as opposed to `mark.innerRadius`/`mark.outerRadius`, which ARE supported — see the Marks table). `marks/arc.ts` reads `radius`/`radius2` only to fire `unsupported` gaps (`encoding:arc-radius`, `encoding:arc-radius2`); a single pie series has one inner/outer radius, not a per-slice value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `detail`                   | ❌ unsupported (all tiers)                                | Declared in the type but never read anywhere in the compiler; grouping-without-encoding has no x-charts equivalent and produces no gap (silently ignored).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `order`                    | ⚠️ partial (arc)                                          | Only `marks/arc.ts` reads `order`, and now applies it: a `field` with an optional ascending/descending `sort` sorts the pie slices (tie-broken by row order; falls back to the slice's aggregated `value` when the order field was consumed by aggregation). An uninterpretable form (multi-field array, sort-by-encoding, field-less aggregate) records a `partial` gap (`encoding:arc-order`) and keeps row order. Not read by any other mark compiler (bar/line/point series order follows color-group iteration order, not an `order` channel).                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `text`                     | ✅ supported                                              | `marks/textMark.ts` renders text marks as overlays; `marks/arc.ts` maps `encoding.text` to the pie series `arcLabel` ('label'/'value'/callback). Translatable `format` strings are applied on text-mark overlays; unmappable configs (multi-line arrays) are `partial` gaps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `tooltip`                  | ⚠️ partial                                                | An `encoding.tooltip` field def (or array) now swaps the default tooltip for a custom `VegaTooltip` (`VegaLiteChart/VegaTooltip.tsx`) that reuses x-charts' tooltip hooks and prefixes the highlighted series values with the spec's declared field labels. Limitation: the compiled rows aren't exposed to the shell, so tooltip fields that aren't part of the x/y/color encoding show as labels only (their per-point values can't be resolved); a `tooltip` with no resolvable fields keeps the built-in `<ChartsTooltip />`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `href`                     | ❌ unsupported (all tiers)                                | Declared in the type but never read anywhere; no gap is fired for it either. Workaround: use external click handlers on the chart container.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `key`                      | ⚠️ ignored                                                | Declared in the type but never read; data is matched by array index (via `categoryIndex`/`categoryKey` on the resolved axis field), not by `key`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `facet` / `row` / `column` | ✅ supported (wrapper)                                    | `<VegaLiteChart />` expands facet channels into a CSS grid of sub-charts (`src/facet`): rows partitioned per facet value, shared quantitative domains + category order injected, per-facet headers. The pure `compileSpec` API still gaps composite specs (render through the component).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## Data & transforms

### Data source

| Feature                                           | Status                     | Notes                                                                                                                                                                                                     |
| :------------------------------------------------ | :------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inline values (`data.values` as object array)     | ✅ supported               | `normalize/index.ts` `resolveRows`.                                                                                                                                                                       |
| Named datasets (`data.name` + `datasets` map)     | ✅ supported               | Resolved via the `datasets` prop (host-provided) merged over `spec.datasets`, host takes precedence; a missing name reports an `unsupported` gap (`data:named-missing`) and falls back to inherited rows. |
| URL loading (`data.url`)                          | ❌ unsupported (all tiers) | `unsupported` gap (`data:url`); no HTTP fetching in the wrapper. Workaround: fetch data yourself and pass via the `data` prop or `datasets`.                                                              |
| String payloads (`data.values` as CSV/TSV string) | ❌ unsupported (all tiers) | `unsupported` gap (`data:string-values`); string parsing not implemented. Workaround: parse to a JSON array first.                                                                                        |
| `data.format` (CSV parsing, delimiter, etc.)      | ⚠️ ignored                 | Declared in the `VegaData` type but never read in `normalize/index.ts`; no gap is fired for it. Data must already be parsed into row objects.                                                             |

### Transforms

Transforms are applied sequentially in order (`transforms/index.ts` `applyTransforms`, plus the inline encoding-level pass `applyEncodingTransforms` in `transforms/encoding.ts` for `aggregate`/`bin`/`timeUnit` declared directly on a channel field def). Unrecognized top-level transform kinds are skipped with a gap.

| Transform       | Status                     | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| :-------------- | :------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aggregate`     | ✅ supported               | `transforms/aggregate.ts` (top-level) and the inline pass in `transforms/encoding.ts`, sharing the op evaluator in `transforms/aggregateOps.ts`. Full group-by aggregation: `count`, `valid`, `missing`, `distinct`, `sum`, `product`, `mean`/`average`, `min`, `max`, `median`, `q1`, `q3`, `variance`, `variancep`, `stdev`, `stdevp`, `stderr`. Encoding-level `argmin`/`argmax` are now implemented (`transforms/encoding.ts`): both the string form (`aggregate: 'argmax'`) and the object form (`aggregate: {argmax: 'b'}`) select the row that extremizes the criterion within each group and read this channel's own `field` off it. An argmin/argmax missing its criterion or the channel's `field` still drops the channel with an `unsupported` gap (`aggregate:argminmax`). (The top-level `aggregate` transform passes argmin/argmax through `evaluateAggregate`, which returns the whole extreme row rather than a scalar field value.)                                                                                         |
| `fold`          | ✅ supported               | Inline in `transforms/index.ts` `applyTransforms` (not a separate module). Pivots columns to rows (key–value pairs); `fold.as` defaults to `['key', 'value']`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `filter`        | ✅ supported               | `transforms/filter.ts`. Field predicates (`{field, equal/lt/lte/gt/gte/range/oneOf/valid}`, optionally with a `timeUnit` qualifier — compared against the raw value with a `partial` gap since it isn't actually truncated first), logical composition (`and`/`or`/`not`, three-valued to fail open on unsupported sub-predicates), and Vega expression strings (via the shared safe evaluator in `transforms/calculate.ts` — **never** `eval()`/`new Function()`). Selection/param predicates and malformed shapes report an `unsupported` gap and keep every row (fail open).                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `calculate`     | ✅ supported               | `transforms/calculate.ts`. A hand-rolled recursive-descent parser/evaluator (never `eval()`) for a safe expression subset: arithmetic, string concatenation, comparisons, ternaries, `&&`/\|\|/`!`, `datum.field`/`datum['field']` access, and an allow-listed function set (`abs`, `round`, `floor`, `ceil`, `sqrt`, `min`, `max`, `length`, `upper`, `lower`, `toNumber`, `toString`, `year`, `month`, `date`). Syntax/semantics outside this subset report an `unsupported` gap (`transform:calculate`) and leave the target field `null`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `bin`           | ✅ supported               | `transforms/bin.ts` (top-level `applyBinTransform`, and inline `applyInlineBin` wired from `transforms/encoding.ts`). d3-style "nice" binning honoring `maxbins` (default 10), an explicit `step`, and an explicit `extent` (values outside an _explicit_ extent are excluded; a _derived_ extent always covers every value). The top-level transform writes `as` (bin start) and `as`+`_end` (or `as[1]`); the inline (encoding-channel) form writes a synthetic `"start–end"` ordinal label column so histograms go through the existing band-scale axis path. `bin: "binned"` (pre-binned data) is now handled (`applyPreBinned` in `bin.ts`): the bin start (`field`) and its bin-end companion — the channel's `x2`/`y2` when present, else the Vega-Lite default `"${field}_end"` — are folded into the same synthetic `"start–end"` ordinal label, so pre-binned histograms take the band-scale path too. Only when no bin-end field can be found is a `partial` gap recorded (`encoding:bin-binned`) and the field rendered unbinned. |
| `timeUnit`      | ✅ supported               | `transforms/timeUnit.ts` (top-level `applyTimeUnitTransform`, and inline `applyInlineTimeUnit`). Calendar truncation for `year`, `quarter`, `month`, `week`, `date`, `hours`, `minutes`, `seconds`, `milliseconds`, and the composites `yearquarter`/`yearmonth`/`yearmonthdate`/`yearweek`/`monthdate`/`hoursminutes`/`hoursminutesseconds` (each truncates to its finest named component while keeping the real calendar date — a documented simplification vs. Vega-Lite's cross-year cyclic alignment for a single unit like `month`). The cyclic `day` (day-of-week) and `dayofyear` units are supported but always report a `partial` gap since they map onto a synthetic reference week / 2012 reference leap year, not the real date. `utc`-prefixed units (`utcyear`, `utcyearmonth`, `utcday`, …) truncate in UTC rather than local time. Genuinely unrecognized units report an `unsupported` gap (`timeUnit:<unit>`) and pass rows through with a `null`/unwritten field.                                                         |
| `window`        | ✅ supported               | `transforms/window.ts`. Ranking ops (`row_number`, `rank`, `dense_rank`, `percent_rank`, `cume_dist`, `ntile`), offset ops (`lag`/`lead`), value ops (`first_value`/`last_value`/`nth_value`), and every `aggregate`-family op (via the shared `evaluateAggregate`) over a sorted, partitioned, peer-group-aware frame (SQL `RANGE`-style peer snapping unless `ignorePeers: true`). **Deviation:** Vega-Lite reorders rows into sort order as its output; this wrapper computes over the sorted view internally but writes results back in the caller's ORIGINAL row order, so a `window` step never corrupts other channels' row-index alignment. `ntile`/`nth_value` with a missing/invalid `param` report an `unsupported` gap (`window:ntile-param`/`window:nth-value-param`) and null the output; a truly unrecognized op reports `window:op:<op>`.                                                                                                                                                                                     |
| `joinaggregate` | ✅ supported               | `transforms/joinaggregate.ts`. Same group-by aggregation as `aggregate` (sharing `evaluateAggregate`), joined back onto every row of the group instead of collapsing to one row per group — row count, order, and existing fields are preserved. Unimplemented ops report an `unsupported` gap (`aggregate:<op>`) and null the field.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `stack`         | ❌ unsupported (all tiers) | Explicit stacking transform not needed; x-charts bar/line infer `stack` from encoding. Use the encoding `stack` property instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `lookup`        | ✅ supported (inline)      | `transforms/lookup.ts` — first-match join on `from.key` with `fields`/`as` renaming, whole-datum-under-`as`, `default` for non-matches, and dotted-path keys on GeoJSON features (choropleth joins). `from.data` must be inline `values`; `url`/named datasets are gaps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `pivot`         | ❌ unsupported (all tiers) | Column pivoting has no x-charts equivalent. Workaround: use `fold` or pivot data in preprocessing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `density`       | ✅ supported               | `transforms/density.ts`. Gaussian KDE per group over a FIXED, evenly spaced grid of `steps + 1` points (default `steps` clamped between `minsteps`/`maxsteps` around 100). Bandwidth defaults to a Scott's-rule estimator (`1.06 · min(stdev, IQR/1.34) · n^(-1/5)`, guarded against a zero spread); `cumulative` uses a Gaussian CDF (Abramowitz–Stegun `erf` approximation); `counts` scales the curve by the group size. **Deviation:** vega-statistics uses an adaptive grid; this wrapper always samples a fixed evenly spaced grid — no gap is reported since the output is numerically close and visually indistinguishable for smooth densities.                                                                                                                                                                                                                                                                                                                                                                                      |
| `regression`    | ✅ supported               | `transforms/regression.ts`. Closed-form OLS fits: `linear` (direct), `log`/`exp`/`pow` (log-linearized OLS — see deviation below), `quad` (degree-2 polynomial), `poly` (degree `min(order ?? 3, pairs - 1)` via a Vandermonde normal-equations solve + Gaussian elimination with partial pivoting). Emits a sampled curve by default (2 endpoints for `linear`, 50 points otherwise, over `extent` or the data's x-range) or one `{coef, rSquared}` summary row per group with `params: true`. Domain violations (`log`/`pow` need `on` > 0; `exp`/`pow` need `regression` > 0) drop the offending rows with a `partial` gap (`transform:regression-domain`); an unrecognized `method` falls back to `linear` with a `partial` gap (`transform:regression-method`). **Deviation:** `exp`/`pow` are fit by log-linearizing (OLS in log-space) rather than vega-statistics' direct nonlinear least squares — exact for noiseless data, slightly biased vs. y-space error for noisy data.                                                       |
| `loess`         | ✅ supported               | `transforms/loess.ts`. Full LOESS (Cleveland's algorithm): a tricube-weighted linear fit at each point over its `span` (`max(2, ceil(bandwidth · n))`, default `bandwidth: 0.3`) nearest x-neighbors, refined by two bisquare-weighted robustness iterations. Groups with fewer than 3 valid points pass through unsmoothed (no gap — too little data to fit, not a translation failure).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `impute`        | ❌ unsupported (all tiers) | Missing-value imputation has no x-charts equivalent. Workaround: impute before passing data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `flatten`       | ❌ unsupported (all tiers) | Nested array flattening has no x-charts equivalent. Workaround: flatten before passing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `sample`        | ❌ unsupported (all tiers) | Stochastic row sampling has no x-charts equivalent. Workaround: sample before passing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `quantile`      | ✅ supported               | `transforms/quantile.ts`. Per-group quantile curves reusing the shared linear-interpolation `quantile()` helper (the same one behind the `median`/`q1`/`q3` aggregate ops). `probs` defaults to a generated series from `step` (default `0.01`): `step/2, step/2 + step, …` while `< 1`. Groups with no numeric values emit nothing (not a gap — an empty curve for an empty group is expected).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

All of the remaining `KNOWN_UNSUPPORTED_TRANSFORMS` (`transforms/index.ts`: `pivot`, `sample`, `stack`, `impute`, `flatten`) plus any other unrecognized top-level transform key report `transform:<kind>` as an `unsupported` gap and are skipped, leaving downstream rows unmodified by that step.

## Scales & axes

### Scale types

`compile/scales.ts` `resolveChannelAxis` resolves positional (x/y) scales. Temporal data on a continuous-friendly mark (line/area/point/rule/tick/errorband) defaults to a continuous `time`/`utc` scale, so points are spaced by real date distance. It falls back to a discrete band/point scale over the sorted date domain (with a `partial` gap, `scale:temporal-point-approximation`) for occurrence marks (`bar`/`rect`/`boxplot`/`errorbar`), an explicit discrete `scale.type`, or a non-ascending `sort`.

| Scale type                                           | Status       | Notes                                                                                                                                                                                                                                                                                                                                   |
| :--------------------------------------------------- | :----------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `linear`                                             | ✅ supported | Default for quantitative axes.                                                                                                                                                                                                                                                                                                          |
| `log`                                                | ✅ supported | Logarithmic scale.                                                                                                                                                                                                                                                                                                                      |
| `pow`                                                | ⚠️ partial   | Scale type maps through, but `scale.exponent` is declared in the `VegaScale` type and never read by `resolveChannelAxis` — the x-charts default exponent is always used, not the spec's value.                                                                                                                                          |
| `sqrt`                                               | ✅ supported | Square-root scale.                                                                                                                                                                                                                                                                                                                      |
| `symlog`                                             | ✅ supported | Scale type maps through, and a numeric `scale.constant` (the symlog linear-region constant) is now forwarded to the x-charts symlog `constant` (`compile/scales.ts`); it is read only on `symlog`, ignored for other scale types.                                                                                                       |
| `time` / `utc`                                       | ✅ supported | Continuous time scale (`scaleType: 'time'`) by default on continuous-friendly marks; `min`/`max` come from `scale.domain` (`domainMin`/`domainMax` and `{unionWith}` object domains are ignored — `partial`). Falls back to a discrete band/point scale for occurrence marks / explicit discrete type / non-ascending sort (see above). |
| `band`                                               | ✅ supported | Categorical; used by default for bar/rect marks (`channelHasBarMark`).                                                                                                                                                                                                                                                                  |
| `point`                                              | ✅ supported | Categorical; used by default for non-bar marks.                                                                                                                                                                                                                                                                                         |
| `ordinal`                                            | ✅ supported | An explicit `scale.type: 'ordinal'` maps to x-charts' `band` scale (`explicitDiscreteScaleType`), matching Vega's own convention that an ordinal position scale is a band scale. (Not "treated as point" — that was true of a prior implementation but is not what the current code does.)                                              |
| Unsupported types (e.g., `sequential`, custom names) | ⚠️ partial   | An unrecognized `scale.type` string falls back to `linear` with a `partial` gap (`scale:<type>`) — the chart still renders (with the wrong scale semantics), it does not drop the axis.                                                                                                                                                 |

Band-scale `padding`/`paddingInner` (Vega-Lite spacing knobs) now map to the band `categoryGapRatio`; `paddingOuter` has no x-charts equivalent and is dropped (`partial` gap) — see the Scale properties table below.

| Autosize                     | ⚠️ ignored                 | `spec.autosize` is declared in the type but never read; `spec.width`/`spec.height` of `'container'` or a step/object form report an `ignored` gap (`size:width-step`/`size:height-step` in `normalize/index.ts`) and fall back to container sizing (the `width`/`height` props on `<VegaLiteChart>`, or the chart's natural container size).                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Font config                  | ❌ unsupported (all tiers) | Not part of the accepted spec grammar; x-charts applies MUI theme fonts unconditionally.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Renderer (SVG vs. Canvas)    | ⚠️ ignored                 | Not part of the accepted spec grammar (Vega-Lite's `config.mark.renderer` isn't in the `VegaLiteSpec` type at all); `<ChartsSurface>` always renders SVG.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

| Feature                                                | Status                     | Notes                                                                                                                                                                                                                                                                                                    |
| :----------------------------------------------------- | :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## How gaps are reported at runtime

When the wrapper encounters untranslatable Vega-Lite features, it collects them as `TranslationGap` objects and returns them via the `onGaps` prop. Each gap has a `code` (e.g., `mark:geoshape`, `encoding:facet`), a human-readable `message` (often including workarounds and tier pointers), a `severity` (unsupported/partial/ignored), and optionally a `path` into the input spec (e.g., `layer[0].encoding.color`).

Example usage:

```tsx
import { VegaLiteChart } from '@mui/x-charts-vega';

const spec = {
  mark: 'geoshape',
  // ...
};

const [gaps, setGaps] = useState([]);

<VegaLiteChart spec={spec} onGaps={setGaps} />;

// gaps[0].code === 'composition:repeat'
// gaps[0].message === '`repeat` view composition has no x-charts equivalent and is not expanded…'
// gaps[0].severity === 'unsupported'
```

Render gaps as warnings in your UI, or use them to fall back to a different visualization. The wrapper always attempts a best-effort render even when gaps are present.
